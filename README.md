# Cloud Engineering Project Roadmap

A curated learning backlog for building practical AWS, cloud infrastructure, Kubernetes, DevOps, security, and observability skills.

> **Important:** This repository is a learning roadmap and checklist. It is not a claim that every listed project has been implemented. Completed, demonstrable work lives in its own project repository.

## Start here

Use the roadmap below to choose a project, then turn the result into a small, reviewable engineering deliverable: architecture, implementation, validation, and a short write-up of trade-offs.

- **[AWS intermediate, advanced & expert project checklist](./aws-intermediate-advanced-expert-projects.md)** — the detailed catalogue and suggested fast-track sequence.
- **[Progressive Delivery Platform on EKS](https://github.com/amit-cloudops-ai/progressive-delivery-eks-platform)** — EKS, GitOps, canary delivery, observability, and incident response.
- **[Multi-App Platform on ECS Fargate](https://github.com/amit-cloudops-ai/fargate-alb-multi-app-demo)** — ECS Fargate, ALB routing, and managed persistence.
- **[Three-Tier AWS Application](https://github.com/amit-cloudops-ai/Devops-3-tire-project-001)** — VPC networking and presentation, application, and data tiers.
- **[HRMS Onboarding Service](https://github.com/amit-cloudops-ai/hrms-onboarding-service)** — serverless onboarding workflows and identity integration.
- **[Kubernetes Learning Journey](https://github.com/amit-cloudops-ai/k8s-learning-journey)** — focused Kubernetes labs from core workloads to operations.
- **[Failsafe Verification](https://github.com/amit-cloudops-ai/failsafe-verification)** — test-gap analysis and verification reporting.

## How to use this repository

1. Pick a project that fills a gap in your skills rather than repeating a project you already have.
2. Create a small scope with an observable success criterion.
3. Implement the project in a dedicated repository or clearly separated lab.
4. Capture evidence: architecture diagram, test results, deployment screenshots, and known limitations.
5. Update the detailed checklist only when you have actually completed the work.

## Recommended portfolio standard

For each finished project, aim to include:

- A clear problem statement and why the design is useful.
- An architecture diagram and a concise request/data flow.
- Reproducible setup and cleanup instructions.
- Security boundaries and cost considerations.
- Tests or validation evidence.
- Trade-offs, failure modes, and next steps.
